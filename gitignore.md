# Правила для игнорирования в GITIGNORE

**Главное правило (Важно!)**

.gitignore работает только для файлов, которые Git еще не отслеживает.

Если файл или папка (например, node_modules) уже были добавлены в Git ранее, то просто добавить их в .gitignore недостаточно — они продолжат отслеживаться.

Как исправить:
Нужно удалить их из индекса Git (файлы на диске останутся на месте):

```
git rm -r --cached node_modules
git commit -m "chore: stop tracking node_modules"
```

 ## 1. Базовые шаблоны

| Шаблон | Что делает? | Пример |
| :--- | :--- | :--- |
| `file.txt` | Игнорирует конкретный файл в любой папке | `secret.txt` |
| `folder/` | Игнорирует всю папку и всё её содержимое | `node_modules/` |
| `*.ext` | Игнорирует все файлы с таким расширением | `*.log`, `*.tmp` |
| `**/pattern` | Ищет совпадения на любой глубине вложенности | `**/temp/` |

 ## 2. Спецсимволы

- `#` — комментарий. Строки, начинающиеся с решетки, игнорируются.

- `!` — исключение. Позволяет «вернуть» файл, который был проигнорирован ранее.

Пример: !README.md (не игнорировать README, даже если все .md файлы в игноре).

- `/` в начале — привязка к корню репозитория.

Пример: /build/ (игнорировать папку build только в корне, но не внутри других папок).

- `?` — заменяет ровно один любой символ.

Пример: file?.txt (совпадет с file1.txt, но не с file10.txt).

## 3. Пример

```gitignore
# Зависимости
node_modules/

# Логи и временные файлы
*.log
npm-debug.log*

# Переменные окружения (секреты)
.env
.env.local

# Системные файлы
.DS_Store
Thumbs.db

# Настройки редакторов
.vscode/
```
