## 1. Создание файла package.json

Чтобы создать package.json, используется команда:

```bash
npm init
```

Она запустит интерактивный опрос (спросит имя проекта, версию, автора и т.д.) и создаст файл.

Если хочешь пропустить вопросы и создать файл с настройками по умолчанию, используется флаг -y:

```bash
npm init -y
```

## 2. Разбор свойств

- **`name`** — имя проекта. Должно быть в нижнем регистре, без пробелов (можно использовать дефисы). По этому имени проект будет публиковаться в npm (если это библиотека).
- **`version`** — версия проекта. Следует правилу SemVer (Семантическое версионирование). Формат: Главная.Второстепенная.Патч (например, 1.0.0). Если ты ломаешь совместимость — меняешь главную, добавляешь фичу — второстепенную, исправляешь баг — патч.
- **`description`** — краткое описание проекта. Отображается при поиске пакета в npm и часто используется для README на GitHub.
- **`main`** — точка входа в приложение.
- **`scripts`** — команды, которые можно запускать через npm run <имя>.
- **`repository`** — информация о том, где хранится код. Это объект, указывающий тип системы контроля версий (git) и URL. Git и npm используют это для связи проекта с исходниками.
- **`keywords`** — массив ключевых слов (тегов). Помогает другим людям найти твой пакет в поиске npm.
- **`author`** — автор проекта.
- **`license`** — лицензия, под которой распространяется код. ISC — очень простая и популярная лицензия с открытым исходным кодом (разрешает использовать, изменять и распространять код). Другие популярные: MIT, Apache-2.0, GPL-3.0.
- **`type`** — определяет, какую систему модулей использовать в проекте.
  - "commonjs" (по умолчанию) — старый стандарт, использует require() и module.exports.
  - "module" — новый стандарт (ES Modules), использует import и export.
- **`bugs`** — ссылка на страницу, где можно сообщить об ошибках (обычно это Issues на GitHub).
- **`homepage`** — ссылка на главную страницу проекта (обычно это README или сайт).
- **`dependencies`** — библиотеки, без которых приложение не сможет работать (например, express для сервера).
- **`devDependencies`** — библиотеки, нужные только разработчикам (линтеры, тесты, сборщики). Например, eslint, mocha, prettier.
